# ⭐ THE ARCHITECTURE BLUEPRINT  
## **“Nova for Data. Velzon for Applications.”**

This is the core principle your Antigravity agent should follow.

### **Nova = Data Administration Layer**
Use Nova when the task is:

- CRUD on Eloquent models  
- Managing canonical records  
- Staff back-office operations  
- Simple forms  
- Resource tables  
- Filters, lenses, actions  
- Bulk data operations  
- Import/export  
- Auditing and logs  
- Permissions and roles  

Nova is your **data admin console**.

### **Velzon = Application UI Layer**
Use Velzon when the task is:

- Dashboards  
- Multi-step workflows  
- AI review queues  
- OCR pipelines  
- Notification routing  
- Escalation dashboards  
- Analytics  
- eCommerce flows  
- Public-facing forms  
- Registration flows  
- Donation flows  
- Email campaign UI  
- Charts, graphs, visualizations  
- Drawers, modals, wizards  
- Anything requiring rich UI/UX  

Velzon is your **application interface**.

# 6. **Integration Pattern**
Nova and Velzon should never “fight” each other.  
They should **cooperate** through the **Service Layer**.

### **Pattern:**
1. Velzon UI → Controller  
2. Controller → Service  
3. Service → Models / Jobs / Notifications  
4. Nova → Views the same data  

### Example:
AI Review Queue (Velzon)  
→ Approve change  
→ CrmSyncService applies update  
→ Contact model updated  
→ Nova shows updated contact  

This keeps your system consistent and auditable.

# ⭐ **Developer Onboarding Guide**

# 1. **High-Level Architecture**
The platform is built on a **three‑layer architecture**:

### **1. Velzon (Application UI Layer)**
- All workflow-driven interfaces  
- Dashboards, analytics, charts  
- AI review queue  
- Notification matrix  
- Institution routing  
- Escalation dashboards  
- Public-facing forms  
- eCommerce flows  
- Email UI  
- Drawers, modals, wizards  

### **2. Laravel Nova (Data Admin Layer)**
- CRUD for canonical data  
- Contacts, institutions, sacraments  
- Safe Environment records  
- Case records  
- Form submissions  
- Notification logs  
- User/role management  

### **3. Laravel Services (Domain Logic Layer)**
- AI extraction  
- OCR pipeline  
- CRM sync  
- Notification routing  
- Escalation logic  
- Payment processing  
- Email integration  
- Jobs + queues  

**Velzon handles the experience.  
Nova handles the data.  
Services handle the logic.**

Here’s the structure you’ll work in:

# 3. **When to Use Nova vs. Velzon**
This is the most important rule in the entire system.

### ✔ Use **Nova** when:
- You’re building CRUD  
- You’re managing canonical data  
- You’re building admin-only data tables  
- You need filters, lenses, actions  
- You need bulk operations  

### ✔ Use **Velzon** when:
- You’re building a workflow  
- You need drawers, modals, wizards  
- You need charts or analytics  
- You’re building public-facing UI  
- You’re building eCommerce  
- You’re building email UI  
- You’re building notification routing  
- You’re building AI review flows  

If you’re unsure, ask:  
**“Is this CRUD or workflow?”**  
That question always gives you the right answer.

---

# 4. **Service Layer Pattern**
All business logic lives in **Services**, not controllers.

### Example pattern:
```
Velzon UI → Controller → Service → Models/Jobs/Notifications
Nova UI   → Nova Action → Service → Models/Jobs/Notifications
```

### Example services:
- `ReviewQueueService`
- `CrmSyncService`
- `NotificationRouter`
- `PaymentService`
- `EmailIntegrationService`
- `OcrPipelineService`

This keeps controllers thin and logic reusable.

---

# 5. **Jobs & Queues**
Anything that might take more than 100ms goes into a job:

- OCR  
- AI extraction  
- CRM sync  
- Notification escalation  
- Email sending  
- Payment processing  

Jobs live in `app/Jobs`.

---

# 6. **Notifications**
Notifications are routed through a unified system:

- Email (SendGrid)  
- SMS (Twilio)  
- Phone calls (Twilio Voice)  
- Telegram  
- Browser push  

Routing is controlled by:

- User preferences  
- Per-event matrix  
- Institution-level routing  
- Escalation rules  

All outbound notifications are logged in `notification_logs`.
